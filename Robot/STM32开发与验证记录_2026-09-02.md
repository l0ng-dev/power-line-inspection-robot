## 4. 当前软件结构与运行行为

当前调用关系为 `main.c → Application/PatrolRobot → BSP/GY906、BSP/Bluetooth、BSP/Ultrasonic、BSP/K230、Middleware/MQTT → BSP/ESP01S → STM32 HAL`。Application 层有必要保留：它负责采样调度、命令解释、遥测组包和状态组织，不直接承担具体 I2C/UART/TIM 硬件操作；这避免把业务调度重新堆回 `main.c`。

- `main.c` 保留 CubeMX 初始化入口、`PatrolRobotApp_Init()`、`PatrolRobotApp_Process()` 以及 UART/TIM HAL 回调转发，继续作为薄入口。
- GY-906 上电等待 250 ms 后通过 I2C1 检查地址，并每 500 ms 读取环境温度和目标温度。
- GY-906 BSP 使用 `0x5A` 七位地址，读取 RAM `0x06`/`0x07`，保留 PEC、传感器错误位和有限次数 I2C 总线恢复；已删除仅供 Watch 使用的总线诊断快照。
- Bluetooth BSP 使用 USART3 单字节中断接收，将 CR/LF 结束的输入组装为最长 63 字节的命令行；维护接收、溢出、UART 错误和发送计数。
- 超声波 BSP 启动 TIM2_CH1 中断捕获，每 100 ms 发出一次 10 μs TRIG 脉冲；依次捕获 ECHO 上升沿和下降沿，以 1 μs 计数换算毫米距离，并在 40 ms 无回波时退出等待和累计超时计数。有效下限为 50 mm；首次 `<50 mm` 进入“过近”，进入后必须达到 `>=60 mm` 才恢复有效。
- Wi-Fi BSP 使用 UART5 Receive-to-Idle 中断和环形缓冲区接收 ESP-01S 数据，在主循环内完成行解析和非阻塞状态迁移；流程包括等待启动、AT 同步、关闭回显、查询版本、Station 模式、禁用旧热点自动连接、主动断开、定向扫描、连接、在线和退避重连。
- Wi-Fi BSP 还提供单路 TCP 非阻塞传输：通过 `AT+CIPSTART` 建立连接，收到 `>` 后发送二进制正文，以 `SEND OK` 确认本地发送完成，并将 `+IPD` 正文按声明长度送入独立环形缓冲区。
- Wi-Fi 状态机分别处理 `OK`、`ERROR`、`FAIL`、`busy`、`WIFI DISCONNECT`、`CLOSED`、`SEND OK` 和 `+CWJAP:<错误码>`；优化版只保留运行所需状态、最后错误、有限重试、退避和 TCP 发送完成计数。
- 公开配置入口为 `Config/network_config.h`；真实热点名称和密码保存在被 Git 忽略的 `Config/network_config.local.h`，本报告不记录实际凭据。
- MQTT BSP 基于 Wi-Fi 单 TCP 通道实现 MQTT 3.1.1，使用巴法云私钥作为 Client ID，订阅基础主题 `Q`，每 5 秒向 `Q/up` 发布中文 JSON 遥测；格式为 `{"距离":"0.40m","物体温度":"28.07度","环境温度":"27.99度","距离状态":"正常"}`。距离保留两位小数，温度保留两位小数；支持下行 PUBLISH、PINGRESP、超时和退避重连。
- 公开私钥加载入口为 `Config/mqtt_secret.h`；真实 MQTT 私钥保存在被 Git 忽略的 `Config/mqtt_secret.local.h`。程序不通过 BLE 输入或回显私钥；凭据如曾公开，应由其所有者立即轮换。
- MQTT 下行消息当前只接收并丢弃，不输出调试提示；尚未定义电机等执行器的云端控制语义，因此不会直接驱动执行器。
- Application 每 5 秒以 UTF-8 分三条发送“距离、物体温度、环境温度”，每条控制在 BLE 20 字节通知载荷内并间隔 80 ms；距离换算为米，最多保留两位小数并去除末尾零，例如 `1.4m`。超时、过近和驱动错误分别反馈“距离:无回波”“距离:过近”“距离:异常”。
- 驱动层和应用层已按统一中文 Doxygen 风格补充文件职责、公共接口和必要关键代码块说明；未对普通判空、赋值和顺序调用进行逐行注释。
- K230 BSP 使用 UART4 单字节中断接收和四行队列，将 CR/LF 结束的完整行留到主循环解析；仅接受 `ALERT,<type>,K230_01`，其中 `<type>` 为 `break`、`heat` 或 `wear`。优化版保留残行丢弃、队列满保护和 UART 错误恢复，删除 Watch 统计变量。
- Application 收到合法 K230 告警后，经现有 USART3 蓝牙链路发送 `K230:<type>\r\n`；三种消息均是 UTF-8 的 ASCII 子集，单次长度分别为 12、11、11 字节，不超过 20 字节通知载荷。
- Application 为 K230 云端事件维护深度为 4 的静态队列，不使用动态内存。合法告警在保留即时蓝牙提示的同时入队；队列满时丢弃最新事件。主循环在 `BSP_MQTT_Process()` 后优先提交队首事件，`HAL_BUSY` 时保留重试，网络离线时最多保留 4 条，恢复后继续发布，不阻塞周期遥测和蓝牙调度。
- K230 视觉事件发布到 `event/up`，载荷字段和值尽量使用中文，设备统一显示为 `K230`，类别映射为“断裂”“热损伤”“磨损”。历史功能版本已通过三类云端显示和断网排队补发验收，且验收期间未发生队列丢弃；优化版已删除对应调试计数，周期遥测继续独立发布到 `Q/up`。这里的主题名称记录当时的本地配置，不是公开仓库默认值。
- K230 标准版当前通过 USB 供电运行 CanMV v1.4.3；GC2093 CSI2 摄像头识别为 1920×1080@60，现有 `best_AnchorBaseDet_can2_5_n_20260827151614.kmodel` 已成功加载，IDE 图像和检测框正常。
- K230 当前有效脚本保存在设备 SD 卡中，使用 IO32/UART3_TXD、IO33/UART3_RXD，115200、8N1；当前仅单向发送。固定 UART 测试入口保留且默认关闭，逐帧性能打印已关闭。
- K230 保留原摄像头推理、连续三帧确认、置信度阈值和 JPEG 保存逻辑；优化脚本使用内置英文点阵字体显示 `BREAK`、`HEAT`、`WEAR`，避免固件缺少默认 FreeType 字体时退出。内部模型标签和目录名继续使用 `break`、`heat_damage`、`wear`。串口告警先于图片保存和 HTTP 上传，网络异常不会阻止 STM32 收到文本告警。
- K230 使用板载 Wi-Fi 和独立敏感配置文件连接网络，通过 HTTP 把 JPEG 上传到当时本地配置的图存储主题；配置文件不写入报告正文或文件指纹。优化版仅保留配置缺失、联网超时、保存、UART 和上传失败信息。
- 热损伤自动上传已实机通过：日志依次出现 `saved`、`alert sent`、`connect success` 和 `cloud upload ok`，巴法云页面显示带“热损伤”中文框的图片。同一持续目标只产生一次告警和上传；连续 3 秒未检出后解除事件锁，用户移开目标再放回时成功产生第二次上传。磨损类别因 `/sdcard/wear` 暂无图片样本，其自动图片上传仍待补测。
- `break`、`heat_damage→heat`、`wear` 已使用已知样本完成本地保存、串口、手机蓝牙和 MQTT 文本事件验收。曾出现一次通道 2 连续三次 `snapshot ... failed(3)` 后清理退出，后续短时运行正常；完整数据集准确率和长时间稳定性仍待补。

> **当时版本的运行方式**：设备上电后自动采样、联网、发布遥测并接收 K230 告警。USART3 继续输出业务遥测和告警，并仅保留 Wi-Fi SSID、密码和连接命令；USART1/VOFA 与 Watch 快照已移除。K230 固定测试入口默认关闭，只在首次接线或故障定位时临时启用。公开仓库默认关闭自动联网，需创建本地配置后才能恢复网络功能。

## 5. 风险与待确认项

| 优先级 | 事项 | 影响 | 关闭条件 |
|---|---|---|---|
| P1 | 超声波新增规则尚未烧录复验 | 50/60 mm 滞回、5 秒遥测和米制显示已编译通过，但手机端实际显示和边界行为尚无新证据 | 烧录当前 HEX，验证固定高度正常测距、盲区安全、40 ms 无回波、恢复测距以及温度/BLE 并行运行 |
| 已处理 | Wi-Fi 与 MQTT 凭据公开风险 | 真实凭据若写入受版本控制的源码、AXF、HEX 或日志会造成泄露 | 真实值已迁移到被 Git 忽略的 `*.local.*` 文件；公开入口默认使用示例值并关闭自动联网。凭据如曾公开仍需立即轮换 |
| P1 | MQTT 当前使用 9501 明文 TCP | 网络链路不提供 TLS 机密性，Client ID 和业务数据可能被同网段监听 | 若部署安全要求包含链路加密，评估 ESP-01S 固件能力并迁移至巴法云 TLS 端口；否则在公开说明中明确限制 |
| P2 | MQTT 30 分钟连续稳定性未完整实测 | 历史版本已有短时连续发布、上下行和断网重连证据，但不能等同于当前交付版的完整时长压力测试 | 后续补做长时间运行，记录云端消息连续性、断网恢复结果和异常现象 |
