# K230 电缆缺陷检测系统使用说明

## 1. 功能说明

本 SD 卡用于 Yahboom K230 电缆缺陷检测设备。K230 上电后自动加载模型并识别以下三类缺陷：

| 模型类别 | 中文含义 | 发送给 STM32 的类型 |
| --- | --- | --- |
| `break` | 断裂 | `break` |
| `heat_damage` | 热损伤 | `heat` |
| `wear` | 磨损 | `wear` |

缺陷连续检出 3 帧且置信度达到 0.30 后，K230 会：

1. 立即通过 UART 向 STM32 发送告警；
2. 将带标注的照片保存到 SD 卡对应类别目录；
3. Wi-Fi 和云配置可用时，将照片上传至巴法云图片接口。

串口告警独立于照片保存和云端上传。抓图、写卡或网络失败不会阻止 K230 向 STM32 发送已经确认的告警。

请不要改名、移动或删除模型、`deploy_config.json`、`det_video.py`、`YbKey.py` 和 `YbRGB.py`。

## 3. 硬件连接

当前程序使用 K230 的 UART3 发送告警，STM32 使用 UART4 接收。

| K230 | STM32G474 | 说明 |
| --- | --- | --- |
| IO32 / UART3_TX | PC11 / UART4_RX | 告警数据 |
| GND | GND | 必须共地 |

通信参数：

- 波特率：115200
- 数据位：8 位
- 停止位：1 位
- 校验位：无
- 流控：无

当前通信为 K230 到 STM32 的单向传输，K230 的 IO33/UART3_RX 无需连接。两块板通过各自 USB 供电时，只连接 IO32、PC11 和公共地，不要连接双方的 5 V 或 3.3 V 电源引脚。通电前应确认两端 UART 均使用兼容的 3.3 V 逻辑电平。

## 4. 首次部署

1. 断开 K230 和 STM32 电源。
2. 将本目录中的内容放在 K230 SD 卡根目录。插卡后，设备中的路径应为 `/sdcard/main.py`，不能多套一层文件夹。
3. 按上表连接 K230 IO32、STM32 PC11 和 GND。
4. 向 STM32 烧录与当前协议匹配的 `PatrolRobot.hex` 固件。
5. 插入 SD 卡并给 STM32、K230 上电。
6. K230 等待约 2 秒后自动加载检测程序。

K230 上电时按住板载按键，可跳过自动检测并进入 IDE 维护状态。

## 5. 正常运行

正常部署时，[`mp_deployment_source/det_video.py`](mp_deployment_source/det_video.py) 中应保持：

```python
UART_TEST_SEND_ON_START = False
```

启动后，CanMV IDE 串口中应依次看到类似信息：

```text
det_infer start
cloud wifi connecting
load kmodel: best_AnchorBaseDet_can2_5_n_20260827151614.kmodel
kmodel loaded
alert uart3 ready: IO32 TX, 115200 8N1
sensor.run ok
```

识别到缺陷后，会看到类似信息：

```text
alert sent: ALERT,break,K230_01
saved: /sdcard/break/break_....jpg
```

STM32 接收的文本报文格式为：

```text
ALERT,<type>,K230_01\r\n
```

有效报文示例：

```text
ALERT,break,K230_01
ALERT,heat,K230_01
ALERT,wear,K230_01
```

STM32 收到报文后，会通过蓝牙输出 `K230:<type>`，并在 MQTT 在线时发布对应的视觉告警事件。视觉告警当前只用于通知和诊断，不直接控制电机。

## 6. K230 与 STM32 固定报文联调

首次接线或更换硬件后，先使用固定报文测试，不依赖摄像头、模型和缺陷样本。

1. 在 `mp_deployment_source/det_video.py` 中临时修改：

   ```python
   UART_TEST_SEND_ON_START = True
   ```

2. 保存文件并重新给 K230 上电。
3. K230 会通过 IO32 每隔 1 秒发送一次固定报文，共发送 3 次：

   ```text
   ALERT,break,K230_01
   ```

4. 检查 STM32 是否收到报文，并确认蓝牙端出现：

   ```text
   K230:break
   ```

5. 测试完成后，将配置恢复为：

   ```python
   UART_TEST_SEND_ON_START = False
   ```

6. 再次上电，确认 K230 进入正常视觉检测。

若固定报文测试失败，先不要调整模型或识别阈值，应依次检查 IO32、PC11、公共地、115200/8N1、STM32 固件以及 UART4 中断接收状态。

## 7. 照片保存

检测照片按类别保存在：

- `/sdcard/break/`
- `/sdcard/heat_damage/`
- `/sdcard/wear/`

同一持续目标只触发一次告警。目标连续消失 3 秒后，事件锁解除；再次检出时可以产生新告警。同类别照片保存冷却时间为 8 秒。

应定期将照片复制到电脑并清理 SD 卡，避免长期运行后空间耗尽。不要删除 `break`、`heat_damage` 和 `wear` 目录本身；如果误删，程序下次启动时会尝试重新创建。

## 8. Wi-Fi 与巴法云配置

云端参数位于：

```text
/sdcard/mp_deployment_source/k230_cloud_secret_local.py
```

该文件需要定义以下变量：

```python
WIFI_SSID = "..."
WIFI_PASSWORD = "..."
BEMFA_UID = "..."
IMAGE_TOPIC = "..."
```

不要在截图、日志、报告或公开仓库中暴露这些值。网络不可用时，K230 仍会继续检测、保存照片并向 STM32 发送 UART 告警。

## 9. 常见问题

### 上电后没有运行检测

- 确认 SD 卡根目录存在 `main.py`；
- 确认上电时没有按住板载按键；
- 确认模型和配置文件位于 `mp_deployment_source`；
- 通过 CanMV IDE 查看异常输出。

### K230 显示检测结果，但 STM32 没有告警

- 先执行固定报文联调；
- 检查 IO32 是否接到 PC11，不能接到 PC10；
- 检查两块板是否共地；
- 确认双方均为 115200、8N1；
- 确认 STM32 已烧录当前 `PatrolRobot.hex`；
- 确认 STM32 UART4 接收中断已经启动。

### 出现 `sensor already inited`、`FreeType init failed` 或显示初始化错误

停止 IDE 程序后，断开 K230 的 USB 和外部电源至少 5 秒，再重新上电。不要连续点击运行按钮反复初始化 Sensor 和 Display。

当前交付脚本使用内置英文点阵字体显示 `BREAK`、`HEAT`、`WEAR`，不依赖 FreeType。若仍出现 `FreeType init failed`，说明 K230 上运行的不是当前 `det_video.py`，应重新复制脚本并完整断电启动。

### 能发送 UART 告警但照片没有上传

- 检查 `k230_cloud_secret_local.py` 是否完整；
- 检查 Wi-Fi 名称、密码以及网络连接；
- 查看 `cloud wifi reconnect timeout` 或 `cloud upload failed` 日志；
- 云端失败不会影响 STM32 串口告警。

### 照片名称显示 1970 年

这表示 K230 尚未获得有效实时时钟。照片名称末尾仍包含运行计数，可避免同一次运行中发生覆盖，但正式长期运行前建议完成联网校时。

## 10. 验收标准

以下项目全部通过后，才能确认 K230 与 STM32 已完成硬件联通：

- K230 能正常启动并加载 KModel；
- 固定报文测试连续发送 3 次；
- STM32 能收到完整的 `ALERT,break,K230_01`；
- 蓝牙端能看到 `K230:break`；
- 正常模式能够分别识别并发送 `break`、`heat` 和 `wear`；
- 照片能够保存到正确目录；
- 画面和保存图片能够显示英文标签 `BREAK`、`HEAT`、`WEAR`；
- 需要云功能时，巴法云上传和 STM32 MQTT 告警均正常；
- 连续运行期间没有重复初始化、异常复位或 SD 卡写入错误。

目前代码语法、K230 报文生成、STM32 协议匹配和 STM32 工程编译已经验证。实际引脚、电平、接线、固件烧录以及板上收发结果必须通过上述步骤实测确认。
